# AstroAI4U - Monthly Subscription Pricing Plans

This document outlines the proposed 3-tier pricing strategy for AstroAI4U, including the monthly credit reset mechanism, core features list, and integration of the upcoming **Astrological Calendar** feature.

---

## Core Rule: Monthly Credit Wipeout & Refresh

To optimize server usage, encourage active engagement, and simplify token management, **credits do not roll over**. 
* Every **30 days** (based on the user's billing cycle), any remaining credits in the user's account are **wiped out** (reset to `0`).
* Simultaneously, the user's monthly quota of credits is **refreshed** based on their active subscription tier.
* Users can still purchase one-off **add-on credit packs** if they run out before the end of the month. These add-on credits are subject to expiration at the end of the current billing cycle.

## New Feature: Astrological Calendar

The Astrological Calendar is an interactive dashboard that blends the user's schedule with celestial activity.

### 1. Check Astrological Events
* **Zodiac Transits & Retrogrades:** Displays planetary shifts (e.g., Mercury Retrograde, Mars entering Scorpio) with easy-to-understand explanations of their energetic influence.
* **Moon Phases:** Tracks New Moons, Full Moons, and Void-of-Course periods, which are critical for spiritual manifestation and planning.
* **Personalized Transit Matches (Pro/VIP):** Highlights how current planet alignments interact specifically with the user's Birth Chart (e.g., "Jupiter transiting your 10th house of career today").

### 2. Add Personal Events
* **Custom Event Logging:** Users can create traditional calendar events (e.g., "Job Interview", "First Date", "Manifestation Session").
* **Astrological Contextualization:** When adding a personal event, the system checks the celestial state at that hour and provides a compatibility or guidance rating (e.g., "Excellent day for communication!").
* **Astro-Reminders (Pro/VIP):** Send notifications when a specific planet transit aligns with an event time.

## Technical Architecture Recommendations

To implement this pricing model and calendar, the following backend changes are recommended:

### 1. MongoDB Database Schema Updates

#### `users` Collection Additions:
```javascript
{
  subscription_tier: { type: String, enum: ['free', 'starter', 'explorer', 'sage'], default: 'free' },
  subscription_status: { type: String, enum: ['active', 'inactive', 'cancelled'] },
  billing_cycle_anchor: { type: Date }, // Used to trigger the credit wipeout
  credits: { type: Number, default: 0 }
}
```

#### `calendar_events` Collection [NEW]:
```javascript
{
  user_id: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
  title: { type: String, required: true },
  description: { type: String },
  start_time: { type: Date, required: true },
  end_time: { type: Date },
  is_astro_event: { type: Boolean, default: false }, // true if generated by celestial data
  astro_metadata: {
    transit: { type: String }, // e.g., "Mercury Sextile Venus"
    influence: { type: String }, // description of the celestial alignment
    intensity: { type: Number }  // 1-5 scale
  },
  created_at: { type: Date, default: Date.now }
}
```

### 2. Implementing Credit Wipeout (Cron / Scheduler)

A daily running worker (using a library like `node-cron` or `agenda` in the Node backend) checks users whose billing cycles end today:
1. Identify users where `billing_cycle_anchor` matches the current day of the month.
2. Wipe out their remaining `credits` balance (set to `0`).
3. Load the credits belonging to their subscription tier (Starter = 50, Explorer = 180, Sage = 450).
4. Update `billing_cycle_anchor` to the next month.
